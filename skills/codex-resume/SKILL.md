# Codex 세션 이어가기

Codex의 세션 기록(`~/.codex/sessions`)에서 재개 패킷을 뽑아, 멈춘 지점부터 이어서 작업한다. 패킷은 기록일 뿐이고, 실제 상태는 디스크와 git이 기준이다.

## 1. 재개 패킷 가져오기

이 스킬의 기본 디렉터리(Base directory)에 있는 `resume.sh`를 실행한다.

```bash
bash "<기본 디렉터리>/resume.sh" --cwd "$PWD"
```

- 사용자가 인자(세션 ID 일부)를 줬으면 `--session <인자>`를 붙인다.
- 종료 코드 2: 이 폴더에서 돈 Codex 세션이 없다는 뜻이다. stderr의 최근 세션 목록을 보여 주고 어느 것을 이어갈지 묻는다. 고르면 `--session <id>`로 다시 실행한다.

## 2. 작업 위치 확인

패킷의 "Codex 작업 폴더"가 현재 폴더와 다르면(예: Claude가 새 worktree에서 열림) Codex의 커밋 안 된 변경은 여기에 없다. 사용자에게 그 사실을 알리고, Codex 작업 폴더에서 이어갈지 묻는다. 확인 없이 다른 폴더의 파일을 고치지 않는다.

## 3. 실제 상태 대조

```bash
git -C "<Codex 작업 폴더>" status --short --branch
git -C "<Codex 작업 폴더>" diff --stat
```

- 패킷의 "바꾼 파일"이 실제로 있는지, 커밋 안 된 변경이 무엇인지 확인한다. 셸 명령(python, sed 등)으로 바꾼 파일은 패킷 목록에 없을 수 있으니 git 결과를 기준으로 삼는다.
- 마지막 진행 코멘트, 마지막 명령, 사고 요약 제목을 보고 어디까지 끝났는지 판단한다. 필요하면 바뀐 파일을 직접 읽는다.

## 4. 짧게 보고

3~5줄로 알린다: Codex가 하던 일 / 끝난 것 / 남은 것. 상태가 사용량 한도면 초기화 시각도 한 줄 덧붙인다.

## 5. 이어서 진행

- "마지막 요청" 중 남은 부분부터 이어간다. 끝난 일은 반복하지 않는다.
- "마지막 요청"이 "1 하고 2 해줘"처럼 앞 대화를 가리키면 "직전 대화"의 Codex 답변에서 무엇을 가리키는지 찾는다.
- 남은 일이 push·배포·삭제처럼 되돌리기 어렵거나, 무엇을 할지 모호하면 먼저 묻는다.
- 상태가 "마지막 턴은 정상 완료됨"이면 이어갈 작업이 없을 수 있다. 최종 답변을 요약하고 다음에 무엇을 할지 묻는다.
